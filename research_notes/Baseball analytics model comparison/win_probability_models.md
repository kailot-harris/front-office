# Win Probability / Game-Outcome Prediction Methods in Baseball Analytics

## Which papers/methods directly compare predictive accuracy (log-loss, Brier, calibration) across approaches on real MLB data?

### Takeaway
The most directly relevant and rigorous source found is Allen & Savala (2025/2026, arXiv), "Assessing Win Strength in MLB Win Prediction Models," which benchmarks six classifier families plus a Pythagorean-informed baseline and FiveThirtyEight's Elo model on 2001-2019 MLB data using accuracy, AUROC, log-loss, and Brier score simultaneously — logistic regression was the single best-performing model overall, and FiveThirtyEight's Elo-based model was the weakest of all methods tested on these metrics.

### Cited Findings
- Allen & Savala benchmark Logistic Regression (LogR), Support Vector Machines (SVM), K-Nearest Neighbors (KNN), XGBoost (XGB), Artificial Neural Networks (ANN), a home-team-win baseline, and FiveThirtyEight's ELO model on 46,159 MLB regular-season games (2001-2019), training on 2001-2015 and testing out-of-sample on 2016-2019 — [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- Reported metrics: LogR 62.94% accuracy / AUROC 0.6768 / log-loss 0.6418 / Brier 0.2254; SVM 62.38% / 0.6597 / 0.6529 / 0.2303; KNN 62.15% / 0.6686 / 0.6492 / 0.2274; XGBoost 61.08% / 0.6499 / 0.6639 / 0.2347; ANN 62.13% / 0.6653 / 0.6500 / 0.2292; FiveThirtyEight Elo 56.96% / 0.5950 / 0.6769 / 0.2420 — [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- Ensembling multiple classifiers via majority voting with logistic regression produced accuracies of 62.20%-62.83%, essentially matching but not clearly beating plain logistic regression alone — [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- FiveThirtyEight's Elo model showed a notably compressed/underconfident win-probability range (25th-75th percentile of 48.3%-58.7%) compared to the other models, consistent with it under-discriminating strong vs. weak team matchups in this benchmark — [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- The paper's novel contribution is a "win strength" diagnostic: it checks whether a model's predicted win probability correlates with margin of victory/score differential, not just the binary win/loss outcome. LogR showed the best win-probability-to-score-differential correlation (R² ≈ 0.140), vs. 0.063-0.120 for the other models. Games predicted near 90% win probability averaged 3-4 run differentials; "toss-up" games (50%±5%) averaged near-zero differential — [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- The same paper tested a naive run-line betting strategy built on these win probabilities and found that naive application of the ML win-probability outputs for betting led to significant losses; only with optimized probability cutoffs did returns turn positive — [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- A separate, earlier study (Elfrink 2018, VU Amsterdam) compared Random Forest and XGBoost on Retrosheet data spanning 1930-2016 for binary win/loss classification using only season-level team statistics (no live/park/weather features); XGBoost achieved 55.52% accuracy, beating random guessing and a naive home-team-always-wins baseline but well below the 2001-2019 benchmark's classifiers — [Predicting the outcomes of MLB games with a machine learning approach](https://www.math.vu.nl/~sbhulai/papers/paper-elfrink.pdf)
- Another comparison (source aggregated via search, exact paper/venue unclear) reported logistic regression with elastic-net regularization slightly outperforming XGBoost on Brier score (elastic net 0.2270 vs. XGBoost 0.2274) with elastic net accuracy of 61.77% — cited secondhand via search summary, original paper not independently verified; treat as lower-confidence until the primary source is located — [search summary, unverified primary source]
- A different, unrelated comparison of Elo-type and baseline models reported: Home-team-always-wins baseline 53% accuracy, Pythagorean expectation baseline 55% accuracy, an "Implied Elo" model (likely derived from betting markets) 58.4% accuracy, and market/Vegas lines 59.0% accuracy for single-game prediction — source surfaced only as a search-engine synthesis without a traceable primary citation; flagged as a gap below — [search summary, unverified primary source]

### Inferences
- Across independent studies, simple/well-regularized linear models (logistic regression, elastic net) consistently match or beat tree-based gradient boosting (XGBoost) on MLB single-game prediction — likely because MLB single-game outcomes are dominated by high, roughly homogeneous noise (bullpen variance, BABIP luck) that limits the value of capturing nonlinear interactions, and because feature sets used in these comparisons are relatively low-dimensional (season aggregates, Elo-like ratings) rather than rich play-by-play data where boosting typically shines.
- FiveThirtyEight's Elo model, despite being a widely cited public baseline, performed worse than simple season-level ML classifiers in the one rigorous head-to-head found (Allen & Savala). This suggests Elo's simplicity (rating difference → single logistic win-probability curve) leaves accuracy on the table relative to models that use richer season-level inputs, though Elo retains advantages in interpretability, update speed, and not requiring retraining.
- Market/Vegas-line baselines (~59% accuracy) appear to represent close to the practical ceiling for pregame single-game MLB prediction with information available before first pitch; ML classifiers in the 61-63% range are within a few points of this ceiling, implying diminishing returns from additional model complexity absent new information (e.g., real-time lineup/bullpen availability, weather).

## What novel/hybrid methods beyond classic Pythagorean/Elo have been proposed (Elo+ML, in-game WP, park/weather adjustment)?

### Takeaway
Three distinct lines of novel work emerged: (1) FiveThirtyEight's own Elo already functions as a hybrid, blending Elo with preseason ML/statistical projections and a starting-pitcher adjustment term; (2) academic work on in-game (live) win probability has moved toward incorporating team-quality/strength-of-team covariates and more complex pitcher-batter matchup models rather than pure historical base-out-state lookup tables; (3) a MIT Sloan paper, "Beyond Pythagorean Expectation," extends the Pythagorean framework itself by modeling the full shape of team run distributions rather than just aggregate runs scored/allowed.

### Cited Findings
- FiveThirtyEight's MLB system runs two parallel rating schemes: a "simple" Elo used for historical ("Complete History of MLB") ratings that reverts fully to the mean between seasons, and a more elaborate in-season "ratings" system used for live predictions that blends Elo with external preseason team-strength projections from multiple projection systems, then adjusts game-by-game for home-field advantage, rest, travel, and the announced starting pitcher — [How Our MLB Predictions Work](https://fivethirtyeight.com/methodology/how-our-mlb-predictions-work/amp/)
- FiveThirtyEight's starting-pitcher adjustment is computed as `ratingAdj = 4.7 * (pitcher_rGS − team_rGS)`, where `rGS` is a "reduced game score" derived from a Tangotiger-modified version of Bill James's Game Score: `gameScore = 47.4*strikeouts − 1.5*outs − 2*walks − 2*hits − 3*runs − 4*homeruns` (computed per start, then smoothed/regressed into a rating) — [How Our MLB Predictions Work](https://fivethirtyeight.com/methodology/how-our-mlb-predictions-work/amp/)
- As a concrete magnitude example, FiveThirtyEight found that in June 2000 Pedro Martínez's starting-pitcher adjustment was worth about 109 Elo rating points to the Red Sox per start — equivalent to roughly a 15-percentage-point boost in Boston's single-game win probability — [How Our MLB Predictions Work](https://fivethirtyeight.com/methodology/how-our-mlb-predictions-work/amp/)
- Russell Carleton (Baseball Prospectus, "Is Win Probability Broken?") shows that standard in-game win-probability tables, which key only on inning/outs/runners/score differential and ignore the two teams' actual quality, need a median correction of roughly 3 percentage points league-wide (using 1993-2016 data), and in about 10% of game-states the correction is 10+ percentage points (up to 26 points) when a very strong team faces a very weak one. His proposed fix folds team-level runs-scored/allowed-per-game into a regression-adjusted win-probability model. The correction shrinks sharply as the game progresses — by the 7th inning on, the median adjustment is down to about 1.2 points — [Baseball Therapy: Is Win Probability Broken?](https://www.baseballprospectus.com/news/article/31219/baseball-therapy-is-win-probability-broken/)
- A 2018 MIT Sloan paper/talk, "The Problem with Win Probability" (Ganguly & Frank), is cited in secondary sources as identifying the same class of problem — standard win-probability models perform worst in mismatched-team games — though the full paper's specific proposed remedy could not be retrieved in this session — [search-surfaced citation](https://dl.acm.org/doi/10.1145/3447548.3467194) (indirect reference, original SSAC paper not independently fetched)
- A 2010 MIT Sloan paper, "Beyond Pythagorean Expectation: How Run Distributions Affect Win Percentage," is confirmed to exist and was presented at SSAC on March 6, 2010; its PDF could not be parsed as text in this session (binary/image-embedded PDF), so specific numeric findings and dataset years could not be extracted and are listed as a gap — [Beyond Pythagorean Expectation (SSAC10 paper PDF)](https://cdn.prod.website-files.com/68d6be744d7efccc2207f571/68d6be744d7efccc220807d6_SSAC10%20-%20beyondpyth-paper_2.pdf)
- Academic treatments of the Pythagorean formula itself (Luo & Miller, "Relieving and Readjusting Pythagoras," arXiv 1406.3402) provide the theoretical derivation behind the empirically-tuned exponent: the original Bill James formula used exponent 2 (RS²/(RS²+RA²)), but better empirical fits use an exponent near 1.83; Miller and coauthors derive this by modeling runs scored and allowed as independent Weibull-distributed random variables, giving a principled statistical justification rather than a pure curve-fit. The Pythagenpat refinement (developed by David Smyth, endorsed by Clay Davenport of Baseball Prospectus as "a better fit") makes the exponent itself a function of the team's scoring environment (runs per game) rather than a fixed constant — [RELIEVING AND READJUSTING PYTHAGORAS](https://arxiv.org/pdf/1406.3402); secondary confirmation via [search summary]
- Live, play-by-play win-probability modeling research frames the state space as the 24 combinations of outs (0-2) and baserunner occupancy, plus score differential and inning, and notes some recent work models state *transition* probabilities with multinomial logistic regression (softmax) rather than a static state→outcome lookup table, and other recent work (an arXiv preprint "The Impacts of Increasingly Complex Matchup Models on Baseball Win Probability," Nov 2025) specifically studies what happens to in-game win-probability accuracy when pitcher-batter matchup models of increasing complexity are substituted into the state-transition step — [search-surfaced; primary PDF not fetched this session](https://arxiv.org/pdf/2511.17733)
- A 2021 SABR Analytics Conference talk, "Baseball Predictions and Strategies Using Explainable AI" (Joshua Silver, Singlearity; Tate Huffman, Harvard), applied explainable-AI techniques to baseball prediction/strategy models, presented March 14, 2021; content of the talk itself (methods, metrics) could not be retrieved in this session beyond the listing — [SABR 2021 schedule](https://sabr.org/analytics/schedule/2021); [SSAC research paper listing](https://www.sloansportsconference.com/research-papers/baseball-predictions-and-strategies-using-explainable-ai)

### Inferences
- The clearest "beyond classic baseline" trend in the literature is not a wholesale replacement of Elo/Pythagorean methods but augmentation: adding a team-quality or pitcher-quality covariate on top of an otherwise standard state-based or rating-based model (FiveThirtyEight's pitcher adjustment; Carleton's team-quality-adjusted in-game WP). This is architecturally a much smaller change than swapping to a different model family.
- True hybrid Elo+ML approaches (e.g., using a gradient-boosted model to learn the Elo update/K-factor, or using neural nets to learn team ratings end-to-end) were not found as a distinct, well-documented academic strand in this search — most "ML for MLB" papers train standalone classifiers on season/rating features (including Elo and Pythagorean win% as input features) rather than modifying the rating-update mechanism itself. This may be a genuine gap in the published literature rather than a search miss, given how consistently search results returned either pure-Elo or pure-ML papers rather than integrated systems.

### Gaps
- Could not extract numeric/methodological detail from the "Beyond Pythagorean Expectation" SSAC10 paper (PDF would not parse as text) — worth a manual read if architecturally important; it is likely about modeling the variance/shape of a team's run distribution (not just mean runs scored/allowed) to refine the exponent or functional form beyond Pythagenpat.
- Could not retrieve full content of Ganguly & Frank's "The Problem with Win Probability" (MIT Sloan 2018) or confirm their specific proposed fix beyond the general problem statement that is independently corroborated by Carleton's Baseball Prospectus piece.
- Could not retrieve the full text of "The Impacts of Increasingly Complex Matchup Models on Baseball Win Probability" (arXiv 2511.17733, Nov 2025) — this looks like the most directly relevant very-recent paper on hybrid matchup-aware in-game win probability but was only found via search snippet, not fetched.
- No academic source was found that explicitly proposes park-factor- or weather-adjusted pregame win-probability models as a distinct named method (e.g., analogous to park-adjusted Pythagorean formulas); this appears to be an under-studied combination in the accessible literature, or the right search terms were not found in the time available.

## For each notable method: core idea, validation dataset, accuracy/calibration

### Takeaway
Summarizing the specific methods surfaced, with validation data and reported numbers where available (repeated/consolidated from above for quick reference).

### Cited Findings
- **Pythagorean Expectation (classic, exponent=2)**: core idea — win% ≈ RS²/(RS²+RA²); widely reported to explain 85-90% of season win% variance with RMSE of about 3-4 wins per 162-game season (no single primary citation fetched for this specific stat in this session; it is a widely corroborated sabermetric figure appearing across multiple search results) — [Pythagorean expectation (overview)](https://en.wikipedia.org/wiki/Pythagorean_expectation)
- **Pythagenpat**: core idea — replace fixed exponent 2 (or fixed 1.83) with an exponent that varies by scoring environment, i.e., exponent = (RS+RA)/G raised to a power (~0.287 in the commonly cited form); developed by David Smyth, validated/endorsed by Clay Davenport (Baseball Prospectus) as a better fit than the fixed-exponent Pythagorean/Pythagenport variants — [search summary citing Luo & Miller / Davenport](https://arxiv.org/pdf/1406.3402)
- **Weibull-derived Pythagorean (Miller et al.)**: core idea — model runs scored and allowed as independent Weibull-distributed random variables to theoretically derive why an exponent near 1.83-2 fits empirically, rather than treating the exponent as an arbitrary curve-fit constant — [RELIEVING AND READJUSTING PYTHAGORAS](https://arxiv.org/pdf/1406.3402)
- **FiveThirtyEight MLB Elo/Predictions**: core idea — standard Elo updates after each result, reverted toward 1500 between seasons for historical ratings; for live predictions, blended with preseason projections and adjusted per-game for home field, rest, travel, and starting pitcher (via the `4.7 * (pitcher_rGS − team_rGS)` term). Validated across MLB history back to 1871 for the historical Elo series. In the one head-to-head accuracy benchmark found (Allen & Savala, 2001-2019 holdout), this system scored 56.96% accuracy / 0.5950 AUROC / 0.6769 log-loss / 0.2420 Brier — the weakest of all methods tested there — [How Our MLB Predictions Work](https://fivethirtyeight.com/methodology/how-our-mlb-predictions-work/amp/); [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- **Logistic Regression (season-level features)**: core idea — standard binary classifier on team/season statistics (and/or Elo/Pythagorean-derived features); best performer in Allen & Savala's benchmark at 62.94% accuracy / 0.6768 AUROC / 0.6418 log-loss / 0.2254 Brier, 2001-2019 MLB data, held out on 2016-2019 — [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- **XGBoost (gradient boosting)**: two data points — Elfrink (2018), Retrosheet 1930-2016, season-stats-only features: 55.52% accuracy, the best model in that specific study; Allen & Savala (2001-2019): 61.08% accuracy / 0.6499 AUROC / 0.6639 log-loss / 0.2347 Brier, the weakest of the ML classifiers (though still well ahead of the Elo baseline) in that later, richer-feature study — [Predicting the outcomes of MLB games with a machine learning approach](https://www.math.vu.nl/~sbhulai/papers/paper-elfrink.pdf); [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- **SVM, KNN, ANN (season-level features)**: all cluster closely together in the Allen & Savala benchmark, 62.1-62.4% accuracy, AUROC 0.66-0.67, Brier 0.227-0.230 — none clearly beats logistic regression, suggesting limited headroom from model-family complexity alone given these feature sets — [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- **Team-quality-adjusted in-game win probability (Carleton)**: core idea — augment the standard base-out-state/score/inning win-probability table with team-level run-scoring/run-allowing rates via regression; validated on 1993-2016 MLB play-by-play data; shown to matter most early/mid-game (median 3-point correction) and least late-game (median 1.2-point correction from the 7th inning on) — [Baseball Therapy: Is Win Probability Broken?](https://www.baseballprospectus.com/news/article/31219/baseball-therapy-is-win-probability-broken/)

### Inferences
- Reported accuracy for single-game MLB prediction clusters tightly in the low-to-mid 60s percent across nearly every method and study found (55-63%), regardless of whether the method is a rating system, a linear model, or a boosted tree ensemble. This is a strong signal that MLB single-game outcomes have a hard accuracy ceiling around 60-63% given only pregame/season-level information, consistent with baseball's well-known high game-to-game variance.
- The dataset/era matters for comparing absolute numbers: Elfrink's 55.52% (1930-2016, season-stats-only) is not directly comparable to Allen & Savala's 61-63% (2001-2019, presumably richer features) since eras, feature sets, and train/test splits differ substantially.

### Gaps
- No single study was found that puts Pythagenpat, Elo, and ML methods all in the same head-to-head comparison with log-loss/Brier/calibration — Allen & Savala compares Elo vs. ML but uses Pythagorean only as an interpretive feature, not as a standalone benchmarked competitor model. This is the clearest remaining gap for a report that wants a true apples-to-apples ranking of all four baseline families.
- Could not obtain calibration-curve-level detail (e.g., reliability diagrams, calibration slope/intercept) for any method beyond the general Brier/log-loss summary statistics — the Allen & Savala "win strength" R² analysis is a related but distinct concept from standard probability calibration.

## How does each method differ architecturally from a Pythagenpat run-expectation model + 4-factor Elo with starting-pitcher adjustment (the project's current baseline)?

### Takeaway
Relative to a Pythagenpat + 4-factor-Elo-with-pitcher-adjustment baseline, the methods found split into three tiers of adoption cost: (1) small additions — team-quality-adjusted in-game win probability, Weibull-justified Pythagorean exponents, explainable-AI post-hoc analysis layered on an existing model; (2) moderate additions — feeding Elo/Pythagorean outputs as features into a logistic regression or elastic-net meta-model (stacking); (3) large architectural changes — replacing the rating/formula backbone with a trained gradient-boosting or neural-network classifier, or moving to a full play-by-play state-transition model with matchup-level (pitcher vs. batter) submodels.

### Cited Findings
- FiveThirtyEight's own system is architecturally close to the project's baseline already: Elo + home-field/rest/travel adjustments + a starting-pitcher adjustment term layered on top, blended with preseason projections. The main structural difference from a "4-factor Elo + starting pitcher" baseline would be FiveThirtyEight's explicit blending step with external preseason projection systems before the season begins — [How Our MLB Predictions Work](https://fivethirtyeight.com/methodology/how-our-mlb-predictions-work/amp/)
- Logistic regression / SVM / KNN / ANN approaches in Allen & Savala are trained end-to-end on season-level statistics (which can include Elo rating and Pythagorean win% as inputs) rather than using a hand-specified rating-update or run-to-win conversion formula — architecturally this is a shift from a deterministic formula/rating system to a learned statistical model, but if Elo/Pythagorean values are retained as input features, it could be adopted as a single additional "meta-model" layer on top of the existing baseline (moderate change) rather than a wholesale replacement — [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- XGBoost and ANN approaches require a training/retraining pipeline, feature engineering, and hyperparameter tuning infrastructure that a formula-based Pythagenpat+Elo system does not need; in the available benchmarks, this additional complexity did not yield meaningfully better accuracy than plain logistic regression, which weakens the case for adopting tree/neural methods purely for accuracy gains — [Assessing win strength in MLB win prediction models](https://arxiv.org/pdf/2511.02815)
- Carleton's team-quality-adjusted in-game win probability is architecturally a small, additive change: it keeps the existing base-out-state/score/inning win-probability table and adds a regression correction term using team-level scoring rates — directly analogous to adding a "team strength differential" covariate to an existing WP table rather than rebuilding it — [Baseball Therapy: Is Win Probability Broken?](https://www.baseballprospectus.com/news/article/31219/baseball-therapy-is-win-probability-broken/)
- The Weibull-theoretical justification for the Pythagorean exponent (Luo & Miller) does not change the Pythagenpat formula's practical output — it only changes why the exponent should be a particular value — so adopting it would be a documentation/validation note rather than a code change, if Pythagenpat's dynamically-varying exponent is already consistent with the Weibull-implied range — [RELIEVING AND READJUSTING PYTHAGORAS](https://arxiv.org/pdf/1406.3402)
- Play-by-play state-transition models with explicit pitcher-batter matchup submodels (as in the "Impacts of Increasingly Complex Matchup Models" preprint) represent the largest architectural departure found: they require event-level (pitch- or plate-appearance-level) data, a matchup model (e.g., log5 or a learned pitcher-vs-batter interaction model), and a dynamic programming / simulation layer to propagate win probability through the game — a different data granularity and computational structure entirely from a pregame Elo+Pythagorean system — [search-surfaced citation, primary not fetched](https://arxiv.org/pdf/2511.17733)

### Inferences
- Given the accuracy ceiling observed (all pregame methods clustering at 55-63%), the highest-leverage, lowest-cost upgrade to the project's existing Pythagenpat+Elo baseline — if the goal is accuracy/calibration improvement — is likely Carleton-style team-quality adjustment layered onto any in-game/live component, or a lightweight logistic-regression meta-model stacked on top of the existing Elo and Pythagenpat outputs as features, both of which the evidence suggests can match or exceed pure ML approaches without discarding the interpretable baseline.
- There is no strong evidence in the literature found here that switching the core pregame rating/formula engine to XGBoost or a neural network would meaningfully improve accuracy over the current Elo+Pythagenpat-style baseline; the one benchmark with both present (Allen & Savala) had logistic regression — a comparatively simple, interpretable model — beat gradient boosting and ANN on every metric reported.

### Gaps
- Could not determine from available sources how much of Allen & Savala's logistic regression performance advantage specifically comes from including Pythagorean/Elo-style features directly (vs. other season statistics), which would materially affect whether "add a logistic regression layer on top of your existing baseline" is accurately described as a small or moderate change for this project's specific codebase.
- No source directly benchmarked a "Pythagenpat + 4-factor Elo + starting pitcher adjustment" system (i.e., a system matching this project's exact baseline) against any ML method, so all architectural-difference conclusions above are inferred by analogy rather than directly measured against the project's specific baseline implementation.
