# Phase 0b Research: Team/Player-Level Statistics for W/L Prediction

**Research date (all fetches below): 2026-10-17**

This file is a live-verified companion to `docs/PHASE0_RESEARCH_PLAN.md` section 3, produced for
GitHub issue #4. It cross-references each statistic against the R-package/function inventory from
issue #2's `docs/research/phase0a-r-packages.md` and, where relevant, the vendor-level findings in
`docs/research/phase0a-vendor-api.md`. It does **not** create or edit
`docs/MLB_REPLICATION_PLAN.md` — that document is assembled later from this and sibling research
files.

Scope: Pythagorean win expectation, run differential, wOBA, wRC+, FIP, xFIP, SIERA, BABIP, fWAR vs.
bWAR, and Statcast barrel rate/exit velocity/expected stats (xBA/xSLG/xwOBA). Every claim is tied to a
source URL and fetch date (2026-10-17 for all, single research session).

## Findings table

| Stat | Definition / current best-practice form | R package/function source (per issue #2) | Notes |
|---|---|---|---|
| **Pythagorean win expectation** | Three live-verified variants, in order of historical development: (1) Bill James' **original exponent-2** form, `Win% = RS² / (RS² + RA²)`, reported RMSE ≈ 4.126 runs; (2) **Pythagenport** (Clay Davenport, Baseball Prospectus), a variable exponent `exponent = 1.50·log10((RS+RA)/G) + 0.45`, reported RMSE ≈ 3.991; (3) **Pythagenpat** (David Smyth), `exponent = ((RS+RA)/G)^0.287`, which Davenport himself endorsed as "simpler, more elegant, and gets the better answer over a wider range." **Current best practice, verified live**: a single fixed exponent of **1.83** is the most commonly cited "better than 2" simplification and is reportedly the one used by baseball-reference.com, but for atypical run environments (high- or low-scoring seasons/leagues) the **variable-exponent Pythagenpat form is preferred** by leading sabermetric sources over a fixed exponent, since a fixed exponent of 2 overstates the run-to-win gap in extreme run environments. Do not hard-code exponent=2 or a single fixed 1.83 as a final constant — flag for empirical re-derivation per `docs/PHASE0_RESEARCH_PLAN.md`'s constants list. | No single `baseballr` function computes Pythagorean win expectation directly; it is a derived formula computed from runs-scored/runs-allowed inputs obtainable via `baseballr::mlb_team_stats()` or `baseballr::mlb_standings()` (MLB Stats API wrappers, confirmed actively maintained in phase0a-r-packages.md) — i.e., sourced from raw team RS/RA, formula applied in-pipeline, not from a package function. | Exponent must be computed/re-derived from the live run environment per Pythagenpat's own formula, not assumed as a fixed historical value. |
| **Run differential** | `Run differential = Runs Scored − Runs Allowed` (Wikipedia's stated definition). Framed as a baseline predictor via its role in the Pythagorean formula (same RS/RA inputs); multiple independent sources report run differential as strongly correlated with winning percentage (one cited analysis reports R² ≈ 0.846 for the direct win%-vs-differential relationship; a separate secondary source claims run differential "explains an average of 87% of variance in season win totals" since 2011 and roughly a 10-run swing ≈ 1 additional win) — treat the specific R²/variance figures as secondary-source claims requiring re-verification against a primary dataset before being hard-coded, per this file's own citation-rigor standard. | Same as Pythagorean row: `baseballr::mlb_team_stats()` / `mlb_standings()` (MLB Stats API wrapper) supplies raw RS/RA; differential is a simple derived field, not a packaged function. | Simpler and more directly observable than Pythagorean win%; worth retaining as a baseline feature alongside (not instead of) the Pythagorean derivation. |
| **wOBA** (Weighted On-Base Average) | FanGraphs' library formula (2013-season example coefficients, which the library itself notes **vary by year** and must be refreshed per season): `wOBA = (0.690×uBB + 0.722×HBP + 0.888×1B + 1.271×2B + 1.616×3B + 2.101×HR) / (AB + BB − IBB + SF + HBP)`. Assigns a run value to each offensive event rather than treating all hits/walks equally; league-average wOBA is designed to track league-average OBP (~.320). | `baseballr::fg_batter_leaders()` / `fg_batter_game_logs()` (FanGraphs wrapper functions, confirmed actively maintained in phase0a-r-packages.md) can source pre-computed wOBA directly from FanGraphs leaderboards without re-implementing the weighting formula in-pipeline. | Coefficients are year-specific; do not hard-code the 2013 example weights as a permanent constant — pull current-year weights from the FanGraphs source via the wrapper rather than recomputing from a stale formula snapshot. |
| **wRC+** (Weighted Runs Created Plus) | Built from wOBA with park and league adjustments: FanGraphs describes the computation as `(((wOBA − lgwOBA) / wOBA Scale) + (lgR/PA)) × PA`, divided by league-average runs created and multiplied by 100, so 100 = league-average hitter in that park/year and the number scales linearly above/below. Explicitly cross-ballpark/cross-era comparable (unlike raw wOBA, which has no park adjustment). | `baseballr::fg_batter_leaders()` (FanGraphs wrapper) — same function family as wOBA; FanGraphs leaderboards expose wRC+ as a precomputed column. | Preferred over raw wOBA specifically when comparing hitters across different parks/years, per its own stated purpose. |
| **FIP** (Fielding Independent Pitching) | Tom Tango's formula: `FIP = ((13×HR) + (3×(BB+HBP)) − (2×K)) / IP + constant`, where the year-specific constant (typically ≈3.10) is derived as `lgERA − (((13×lgHR)+(3×(lgBB+lgHBP))−(2×lgK))/lgIP)` so FIP sits on an ERA-comparable scale. Designed to isolate pitcher skill from fielding/sequencing/luck by using only strikeouts, walks, HBP, and home runs. | `baseballr::fg_pitcher_leaders()` / `fg_pitcher_game_logs()` (FanGraphs wrapper, actively maintained per phase0a-r-packages.md) exposes FIP as a precomputed leaderboard column. | Constant is year-specific and must be re-derived each season from that season's league totals, not hard-coded. |
| **xFIP** (Expected FIP) | Conceived by Dave Studeman: replaces a pitcher's actual home-run total with `flyball rate × league-average HR-per-flyball rate`, on the premise that a pitcher's flyball rate is a repeatable skill but the fraction of those flyballs that leave the park is mostly not. Same scale/constant mechanics as FIP otherwise. | `baseballr::fg_pitcher_leaders()` (FanGraphs wrapper) — same function family as FIP; xFIP is a standard FanGraphs leaderboard column. | Use when a pitcher's HR/FB rate looks like an outlier relative to league average — same regression logic as BABIP below, applied to home runs instead of balls in play generally. |
| **SIERA** (Skill-Interactive ERA) | FanGraphs' library describes SIERA as the stat that, unlike FIP/xFIP (which largely disregard balls in play), explicitly incorporates batted-ball outcomes and nonlinear interactions between strikeout rate, walk rate, and groundball/flyball rate — e.g. elite strikeout pitchers tend to generate weaker contact/lower BABIP, and groundball rate interacts with double-play opportunities. Per the library page, SIERA is "only marginally more predictive than xFIP overall" despite the added modeling complexity. | None of `baseballr`'s confirmed FanGraphs wrapper functions (`fg_pitcher_leaders()`, etc.) were verified in phase0a-r-packages.md to explicitly list SIERA as a returned column — **flag as unconfirmed**: re-verify against the live `fg_pitcher_leaders()` return schema before assuming SIERA is available without a direct FanGraphs scrape (which carries the ToS risk already flagged in phase0a-vendor-api.md). | Per FanGraphs' own framing, SIERA is marginal over xFIP for prediction despite being more complex — not an automatic upgrade. |
| **BABIP** (Batting Average on Balls In Play) | `BABIP = (H − HR) / (AB − K − HR + SF)`. For pitchers specifically, FanGraphs' library states pitchers have "almost no control over what happens to a ball once it is put in play" (outside K/BB/HR), so an extreme BABIP (high or low relative to the ~.300 league baseline) signals likely regression toward the mean rather than a real skill change; batters exert more control over their own BABIP than pitchers do, so the same extreme-value logic applies more cautiously to hitters (single-season spikes still regress; career-level BABIP is more meaningful for hitters). | `baseballr::fg_pitcher_leaders()` / `fg_batter_leaders()` (FanGraphs wrapper) — BABIP is a standard column on both pitcher and batter leaderboards. | Use explicitly as a luck/regression flag, not a skill metric on its own — especially for pitchers. |
| **fWAR vs. bWAR** (WAR variants — NOT interchangeable) | **Pitcher valuation (biggest divergence):** fWAR (FanGraphs) starts from **FIP** (strikeouts/walks/HBP/HR only — fielding-independent), while bWAR (Baseball-Reference) starts from **Runs Allowed per 9 (RA9)** — i.e., actual runs allowed including the team defense's contribution. Effect: a groundball pitcher with elite defense behind him grades higher in bWAR than fWAR; a high-strikeout pitcher on a poor defensive team grades higher in fWAR than bWAR. **Defensive-value components:** bWAR incorporates Baseball Info Solutions' **Defensive Runs Saved (DRS)** (with Batted Ball Timer data from 2003 onward) plus **Total Zone Rating (TZR)** for earlier eras; fWAR uses **Ultimate Zone Rating (UZR)** from 2002 onward (TZR before that), supplemented by Statcast **Outs Above Average (OAA)** and catcher-framing runs (FRM) — these are built from different underlying defensive-metric providers/methodologies, not the same number relabeled. **Replacement-level baseline:** both systems anchor to a similarly-defined "freely available Triple-A/waiver-wire talent" replacement level (sources cited a recent ~.294 win% / 48-114 win-loss-equivalent baseline for both), but bWAR additionally adjusts that baseline for league strength/quality of competition in a way fWAR does not, per the comparison source. **Conclusion for this repo**: fWAR and bWAR for the same player-season can and do diverge meaningfully, especially for pitchers — pick one source explicitly in any build-phase config rather than treating the two as interchangeable or averaging them. | `baseballr::fg_batter_leaders()` / `fg_pitcher_leaders()` (FanGraphs wrapper, confirmed maintained) sources **fWAR** directly. **No `baseballr` function was confirmed in phase0a-r-packages.md to source bWAR** — `baseballr`'s Baseball-Reference-backed functions (e.g. `bref_team_results()`-style) were specifically flagged in phase0a-r-packages.md as reporting live HTTP 403 breakage as of an Aug 21, 2026 issue report, so bWAR access through `baseballr` should be treated as currently unreliable, not just unconfirmed. | This is the row issue #4 explicitly requires not be treated as interchangeable — see methodological breakdown above. |
| **Statcast barrel rate / exit velocity / expected stats (xBA, xSLG, xwOBA)** | **Barrel**: a batted ball whose exit-velocity/launch-angle combination historically produces a minimum .500 expected batting average and 1.500 expected slugging percentage — concretely, roughly 98+ mph exit velocity paired with a 26–30° launch angle, with the qualifying launch-angle window widening as exit velocity increases above that floor (per MLB.com's Statcast glossary description surfaced via search; direct fetch of `mlb.com/glossary/statcast/barrel` returned HTTP 406, so this definition is corroborated via search-result text rather than a direct page fetch — flag for re-verification via an alternate fetch path before treating the exact angle/velocity thresholds as final). **Exit velocity**: speed in mph of the ball off the bat. **xBA**: probability a given batted ball becomes a hit, assigned from the historical outcomes of comparable batted balls (exit velocity + launch angle), per Baseball Savant's own `expected_statistics` leaderboard page (live-fetched). **xwOBA**: built the same way as xBA/xSLG but combined into the wOBA weighting scale, using exit velocity, launch angle, and — for certain batted-ball types — **Sprint Speed**, per the same live-fetched Savant page; stated purpose is to describe quality/amount of contact independent of defense and park, as a potential *leading indicator* that can diverge from (and precede) regression in the actual box-score stat (BA/SLG/wOBA) it's an "expected" counterpart to. | `baseballr::statcast_search()`, `statcast_leaderboards()`, `code_barrel()`, `linear_weights_savant()` (Baseball Savant/Statcast wrapper functions, confirmed actively maintained in phase0a-r-packages.md) are the direct R sourcing path; phase0a-vendor-api.md separately confirmed the raw Baseball Savant CSV endpoint (`statcast_search/csv`) carries exit-velocity fields from 2017 onward (Statcast-era) vs. 2008-16 PITCHf/x-adjusted values, and flagged a 2026 strike-zone reference-point change — relevant context for any barrel/xBA feature spanning that boundary. | Treat as a leading indicator relative to lagging box-score stats, per Savant's own framing — a gap between actual and expected stats is the signal, not either number alone. |
